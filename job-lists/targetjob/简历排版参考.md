## 默认结构

采用「姓名与岗位方向 → 联系方式 → 教育背景 → 项目与研究经历 → 工作经历 → 论文发表 → 专业技能」。

项目靠前，便于先看到岗位相关证据；技能框放在页尾，汇总前文已经体现的能力。按岗位调整项目顺序，不强制每份简历都列出全部项目或论文。

- 页眉左侧中文姓名与英文姓名，右侧目标岗位方向；联系方式独占一行。
- 教育条目左侧学校与学位，右侧日期；预计毕业明确标注「预计」。
- 项目标题左侧项目名与仓库链接，右侧时间；下一行以较小字号列出技术栈。
- 每个项目通常写 2–3 条，重点项目可写 4 条。先说明解决的问题，再写实现方法与可核实的结果。
- 论文保留作者顺序、研究主题、期刊、日期和 DOI；页面有余量时增加一句研究说明。
- 技能按编程基础、岗位相关技术、工程实践和英语能力组织；较长的技能行先精简措辞。

| 项目 | 当前设置 |

| 字体 | Noto Sans SC，后备 Noto Sans / Microsoft YaHei |
| 正文 | 11 pt，颜色 `#253441`，左对齐 |
| 姓名 / 章节 / 项目标题 | 26 / 12.5 / 11 pt，深蓝色 `#173650` |
| 次要信息 | 9.1–10 pt，灰色 `#667481` |
| 强调色 / 分隔线 / 技能背景 | `#287486` / `#CCD9DF` / `#F3F7F8` |
| 正文 leading / 列表 spacing / 章节 above | 默认 0.96 em / 0.60 em / 0.46 cm |
| 软件开发版覆盖值 | 1.05 em / 0.75 em / 0.50 cm |
| 章节 below / 项目 above | 0.16 cm / 0.34 cm |
| 论文条目 below | 0.45 cm |
| 技能框 | 10.2 pt，左右内边距 0.26 cm、上下 0.27 cm，整体禁止跨页 |

`leading` 表示 Typst 的额外行间距，不是总行高倍数；`list-spacing` 是列表项间距。不要把其他排版工具的「1 倍行距」直接套到这些参数上。

当前机器可用 Noto Sans SC。换机器后先运行 `typst fonts` 确认字体；字体变化会影响英文宽度、换行和整页高度，必须重新渲染检查。

## 留白过多时如何调整

1. 先核对 PDF 是否由当前 `.typ` 导出，并检查是否有多余空块、重复间距或意外分页。
2. 对照参考版检查字体、页边距与模块顺序，再调正文、列表和章节间距；保留 11 pt 正文作为起点。
3. 仍有明显留白时，从原始记录补充最相关的技术方法、评测口径或功能细节。通常先丰富重点项目，再恢复论文研究说明。
4. 句子换行后若只剩一两个词，调整措辞或在自然语义位置换行。`#box[...]` 只用于短指标与短技术名词，避免大段文字被强制挤到下一行。
5. 每次修改后立刻编译、确认页数并查看 PNG；不要等全部简历改完再验证。

## 复用与验证

在与现有公司目录同级的新公司目录中，复制最接近岗位的 `.typ`，保留导入并修改文档标题、方向和项目内容：

```typst
#import "../简历样式.typ": *
#show: resume-style
```

只有内容密度需要时才使用覆盖参数，例如软件版：

```typst
#show: resume-style.with(leading: 1.05em, list-spacing: 0.75em, section-gap: 0.50cm)
```

Windows PowerShell 示例，在经历库根目录（含 `AGENTS.md` 的 `Resume/`）执行；新岗位替换两个文件路径：

```powershell
& './resume/.local/bin/typst.exe' compile --root . --font-path resume/fonts 'job-lists/targetjob/大众汽车中国-VCTC/简历-研发类-AI.typ' 'job-lists/targetjob/大众汽车中国-VCTC/简历-研发类-AI.pdf'
if ($LASTEXITCODE -ne 0) { throw 'Typst 编译失败' }
pdfinfo 'job-lists/targetjob/大众汽车中国-VCTC/简历-研发类-AI.pdf'
New-Item -ItemType Directory -Force -Path '../tmp/pdfs' | Out-Null
pdftoppm -scale-to 1600 -png 'job-lists/targetjob/大众汽车中国-VCTC/简历-研发类-AI.pdf' '../tmp/pdfs/resume-review'
```

确认页数为 1，查看所有渲染页，检查正文与日期对齐、文字没有裁切或重叠、页尾完整、技能框没有跨页；同时检查邮箱、电话、仓库和 DOI 的链接目标。文本提取用于核对内容与位置，不能代替视觉检查。

新增岗位或参考文件时同步更新[经历库索引](../../AGENTS.md)和公司 README。公共样式变化后立即验证所有引用它的简历。单个源文件超过 400 行时提醒重构，把样式或公共组件拆出，保持岗位内容集中。

### 2. 澄清 LoRA 的 zero-shot 与结果口径

「zero-shot 结果集完全匹配率 73.47%」容易被理解为没有训练就取得该结果。这里是已经微调的模型，在推理提示中不提供示例。训练、推理提示与评测集必须分开表达。

建议结果句：

> 在 GeoQuery 的 49 条开发样本上，采用不含示例的推理提示与相同解码、评分条件，查询结果集完全匹配率由未微调模型的 2.04% 提升至 LoRA 模型的 73.47%。

如篇幅允许，可补充 SQL 可执行率 91.84%，展示生成的语法可用性与查询语义正确性两个方面。保留「开发集」限定，不称为测试集成绩或跨数据库泛化效果；数据来自[LoRA 项目记录](../../projects/项目-Text-to-SQL-LLM.md)。
